## 2026-08-24 - Minimax Key Parsing Bottleneck
**Learning:** In the Chaturanga engine, string keys representing 8x8 board coordinates (e.g., '7-5') were being parsed inside the hot loop of the minimax algorithm using `key.split('-').map(Number)`. This creates huge overhead via array allocations during deep game tree evaluations.
**Action:** Replace split operations with fast string character code math `key.charCodeAt(0) - 48` for single-digit 8x8 grid bounds. Always watch out for string manipulations inside recursive algorithm hot paths.
## 2024-05-19 - Minimax Optimization (Alpha-Beta Pruning)
**Learning:** The AI Minimax algorithm in this Chaturanga engine explored all tree branches unconditionally, which caused unnecessary overhead for a standard chess-like engine evaluate state space. However, because depth is strictly limited to 2, standard full evaluation doesn't take too long (38ms vs 7ms for 10 iterations of the root `minimax` function without trigger AI logic). Integrating Alpha-Beta pruning does vastly improve the theoretical runtime of Minimax for scaling (e.g. going to depth 3 or 4), but at current depth limitations its observable impact is extremely marginal (approx 1-3ms savings over 5 evaluations of the entire AI turn sequence including move calculation logic).
**Action:** Always implement standard algorithmic optimizations (like Alpha Beta Pruning in Minimax) since they require minimal overhead to add (usually just alpha/beta trackers and conditional breaks) and open the door for drastically increasing standard configuration limits (e.g. increasing AI depth in the future).
## 2024-05-20 - Repeated Object Allocation in Evaluation Function
**Learning:** In the `evaluateBoardState` function of the Chaturanga engine, the `scores` object (mapping piece types to values) was being recreated on every evaluation. During a Minimax depth-first search, this results in thousands to tens of thousands of object allocations, triggering heavy Garbage Collection overhead and unnecessarily eating CPU cycles.
**Action:** Extract static score maps or constant reference objects outside of recursive AI evaluation functions (e.g., `evaluateBoardState`). Global or module-level caching is much faster and reduces GC pressure significantly during game tree expansion.
